# Full200Mb European validation recovery

The predecessor failed before its first scientific output write. Its `generation/` directory is empty, its native stage never started, and `actual_wait.json` records exit 1 with the owned family and group absent. The in-memory ancestry, target extraction, and mutation work was lost. There is no completed generation receipt or disk checkpoint that can be resumed. Recovery must rerun the same preregistered parent and exact seeds in a fresh output scope; it must not select a new parent, shorten the 200Mb interval, or redraw seeds.

The stored monitor error is `FileNotFoundError(2, 'No such file or directory')`. The old monitor saved only `repr(error)`, which omits the exception filename and internal traceback. Therefore the exact historical filename cannot be recovered from these logs. The demonstrated source-level race is the guardian's `status.tmp` to `status.json` atomic replacement: `measure()` lists the temporary entry, the guardian renames it, and `measure()` then calls `lstat()` on the vanished entry. A deterministic CPU test reproduces that exact failure in sealed `aggregate_guard_v2.py`. The generator failed at its next guard call, after completing the in-memory simulation work. The failure predates cleanup.

The narrow repair recognizes only a vanished root-level `status.tmp`, remeasures its canonical ordinary single-link `status.json` replacement, and charges those bytes conservatively. Unknown missing files, a missing replacement, symlinks, hardlinks, EIO, and EACCES remain errors. `/proc` process enumeration already tolerated disappeared process entries in the predecessor; the successor preserves and tests this behavior while retaining true I/O failures. Future monitor failures record the exception filename, errno, type, stage, timestamp, and traceback.

All total-job, generation-stage, native-stage, and native-per-step elapsed-time cutoffs are removed from successor execution. The pinned native configuration remains unchanged as provenance; its legacy timeout field is not enforced by the successor native supervisor, and terminal records explicitly state this policy. Fresh guardian status, sample age, resource ceilings, execution holds, owned-process identity checks, bounded startup receipt waiting, pipe draining, and TERM/KILL cleanup remain operational safeguards. No original files, simulation parameters, dates, sampling settings, or existing processes were changed.

The proposed scope is `research/efficiency_20261027/root/runs/european_independent_validation_200mb_v2_no_timeouts`; it is not created by preparation. The original failed fullVAL scope and both failed shortVAL scopes are retained with pinned evidence and a combined 16GiB + 128MiB allowance in other-project commitments. The successor still requires the original 128983236608-byte aggregate reservation, 128GiB host RSS ceiling, stage output caps, and global 1.2TB project envelope. ROOT must bind current queue state, current peers, and current other-project commitments before launch.

`CPU_TESTS.json` documents deterministic status replacement, true filesystem errors, transient process disappearance, no elapsed-time cutoffs, liveness/resource safeguards, complete monitor diagnostics, immediate/native nonzero exits, stale process snapshots, adopted-child failures, forced cleanup of persistent owned descendants, and isolation of an unrelated session.
