Primitive-input census addendum
24 October 2026. Source-only independent audit; no measurement/model rerun.

Verdict: PASS for sufficiency of the symbolic FIRST-SWEEP UPWARD dependency keys on the sealed FP32 American first-128-tree packet. No missing consumed primitive was found in that scope. This is a material positive refinement of the earlier conservative source-ID census. It does not qualify an implemented shared training executor or the complete TreeLoom predictor.

The recorded new result has 114,794 unique upward keys among 317,897 occurrences: 63.8896 percent repeated occurrences under this sufficient-key policy. It also reports 445 distinct raw 15-dimensional site-MLP inputs, 2,709 base keys and 202,630 raw gate keys. The earlier zero-reuse result keyed observation source identities and sample columns; it was conservative and cannot be used as evidence of absent primitive-computation sharing. The preserved earlier review explicitly allowed that distinction. Update current README/decision prose to show both results and their policies; preserve the original evidence artifacts.

The key audit

checkpoint_variation.py:28-44 reconstructs the actual American _site_chunk inputs: six selected log donor-frequency channels, six availability indicators, selected panel log-frequency, site entropy and call flag. Every sample with the same allele at a given site receives exactly those same fields in the actual source; selecting one representative for that site/allele is valid. Missing calls remain distinguishable through the raw call flag and zeroing rule. These are bytes of supplied/preprocessed primitive values, not current learned embeddings. The American model has no row-wise dropout or normalization across sites/samples in this MLP.

Lines 55-66 retain the ordered token sequence in each original global 256-site chunk segment of the hold, together with exact FP32 span. This is enough to recover mean/max/count/empty pooling and its chunk-wise arithmetic graph. The actual encoder pools each hold independently, then adds its chunk sums/counts and takes chunk maxima in source order. Absolute chunk number, another hold's rows and sample column index determine routing, not additional numeric input to this local computation. At amax ties a later shared training implementation must still preserve multiplicities and the original derivative semantics.

The base key also contains reference_class, raw FP32 sample age, node age, root status and sampled status. Those fields determine the three-class one-hot/unknown features, normalized ages, node projection and sampled-node injection in static_model_v2.prepare_tree_base_v1. Omitting sample identity from this COMPUTATION key is legitimate: the local numeric encoder contains no sample-ID embedding. Distinct sample occurrences and readout/history routes must remain distinct. This is sharing arithmetic, not identifying two biological haplotypes.

Lines 68-78 include exact bytes of all four geometry and five support fields. Equality is sufficient for the actual gate functions, including the log transform of support count. Reconstructing children by the supplied upward_children arrays preserves each parent's original message order. The upward key contains its own base key, max(1, child count), and ordered pairs of child-upward key plus child gate key. These match the actual PyG child transformation, gate multiplication, division by current parent degree, sum aggregation, update, residual and per-row LayerNorm. A node's own incoming gate/parent context is not consumed by its upward update, so its omission from that state key is correct. It matters later for the message to its parent or for outside context.

The proof assumes the sealed packet contract: FP32 floating fields, complete original trees, one occurrence per sample column in each hold, validated levels and child routing, finite original features, fixed model operator/parameter mapping, and the recorded global chunk alignment. The helper is a bounded diagnostic, not a general packet validator. A production compiler should explicitly validate those prerequisites and bind model/config/source identities as part of the cache contract.

Limits on interpretation

- This is an occurrence-count census, not a FLOP-weighted saving. Leaf and internal operations, MLPs, gates, messages, sums and routing have different costs. Report the leaf/internal breakdown before attributing reuse to deep internal genealogy computation. A count can be large even if difficult internal/outside operations remain unique.
- The census reconstructs sufficient symbolic computation identities; it does not execute the shared keys and compare values/gradients. Changed tensor batch shapes, CPU/GPU kernels and parallel reductions can alter FP32 rounding. The terminal packet chunk has fewer unrelated-hold rows than the full parent. There is no mathematical cross-hold pooling, but full-parent kernel parity is still untested.
- Learned values must be fresh for each optimizer update. Share a node only within that update's autograd graph, retain all downstream occurrence multiplicities and preserve original loss weights. Equal hidden values with different source Jacobians remain an invalid merge rule. Source-key equality is checkpoint-independent; the reported saved-94 spectra are checkpoint-specific.
- No outside-state, second-sweep structural/episode/history injection, genomic GRU, decoder or final prediction is covered by the 63.8896 percent number. The second sweep can destroy first-sweep sharing. Distinct sample/history routing is not supplied by the key census itself and needs explicit occurrence maps in an executor.
- The 445-input count motivates exact unique-MLP evaluation plus gather/scatter as a specific opportunity. It does not remove dense per-site/per-haplotype pooling work. The recorded Python census took 3.38175 seconds, versus 0.88972 seconds for current base/site encoding and 0.33625 seconds for the first cavity sweep on this CPU packet. Cached compilation may amortize, but no end-to-end speedup follows from those different operations/timings.
- The spectral groups are intentionally different from exact reuse keys: they keep native node plus age/root/sample-ordered shape; message groups additionally condition on parent ID, geometry and degree while permitting support/forcing variation. Their shared 32-channel residual eigenspectrum is a descriptive low-rank diagnostic. Concentrated residual L2 energy is not ancestry accuracy, boundary recall, calibration, a Jacobian/gradient bound, an adaptive-rank theorem or evidence that removing residual components is safe. No approximation should be selected from energy alone.
