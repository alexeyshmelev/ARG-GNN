# Prospective frozen-checkpoint evaluation

This phase evaluates the actual H039 pass-5 and pass-10 checkpoints from the fixed three-arm TRAIN stage. It does not optimize a model, instantiate an optimizer, write to the training scope, revise the schedule or use TRAIN/outer truth. Each arm is selected from its original two checkpoint candidates using all eight registered internal VAL parents: maximum equal-parent Present182 exact-span accuracy, then lower NLL, then earlier pass. The scorer, mass construction and FP32 parent aggregation remain the existing H038 functions.

The representation changes storage only. Both the plain model and directed CRF produce one complete C4 logit/marginal row per native hold and query. The original dense readout repeats those rows through the observed bank's exact integer readout_hold vector. A rowwise C4 softmax commutes with this row lookup. Keeping raw FP32 native-hold probabilities and applying native_probability[readout_hold] therefore represents the original complete grid without interpolation, quantization, probability floors, renormalization, discarded queries or changed physical support.

For every requested pass, inference completes all three arms on all eight VAL parents. All 24 complete [native_holds,686,4] probability arrays are held immutable in CPU RAM. The worker publishes one compact JSON per prediction, recording a SHA256 of its actual contiguous FP32 bytes and the shape/dtype; hashes of the exact readout mapping, native spans, original physical positions/edges, retained fixed-grid indexes, query identities and cohorts; and the actual checkpoint, training input/config/phase, observation/cache/sidecar and evaluator/source-manifest references. A 24-seal matrix JSON is published and reverified before the truth gate opens. For the two-pass run, both matrices are complete before the first VAL truth read.

Only after that barrier does the original FullPanelExternalTargetV1 decode each eight-parent VAL truth binding and create the unchanged expected-Present182 mass_cache_v1. One parent/arm grid is expanded transiently in CPU RAM in the original readout order, passed directly to unchanged score_primary_v1(backend=numpy), and discarded. No dense or native prediction arrays are saved to disk, and no blockwise sum reordering or alternate scorer is used. Original means_v1 performs the equal-parent FP32 aggregation.

The JSON seals certify process-local immutable prediction content and provenance; they are not durable prediction arrays. Reproduction requires the retained actual checkpoints, original observed cache/witness bytes and pinned sources/runtime. If the worker fails or exits, RAM predictions cannot be recovered from JSON alone. Evaluation must be independently reproduced before any new scoring; the driver does not automatically replay a failed scope.

The output reservation is one fresh 15,000,000-byte scope, including a 2,000,000-byte original lease/title/device qualification allowance. It contains JSON seals, matrix barriers, scores, selection and actual supervisor evidence. The targeted missing-marker helper and actual v9 marker remain explicitly bound. Scientific execution dependencies and metadata use 44 reservation bindings; transitive sources are SHA-bound by one manifest, avoiding individual reservation bindings for historical TRAIN drivers that evaluation does not execute.

An optional fixed-pass-5 run is allowed only after all three actual pass-5 checkpoint states and their group receipt exist. It uses the same all-24 barrier and original scorer, produces pass-5 scores, and leaves final selection deferred. Its capability explicitly denies optimization and cannot alter the continuing fixed TRAIN stage. A complete pass-5/pass-10 run remains necessary for final checkpoint selection.
