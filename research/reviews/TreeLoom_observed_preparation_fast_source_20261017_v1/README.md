## Concrete implementation

- `observations_fast_v1.py:encode_block` explicitly handles every connected
  hold and the existing zero-SNP all-sampled/all-isolated case. The legacy
  connected early return is removed, so connected holds cannot escape to the
  old Python support sweep. All original raw topology/chronology/sample/date/
  leaf/interval/allele checks remain. Each tree's already validated native
  layout is reused for the Torch/PyG kernel and original geometry/level arrays;
  the kernel does not trigger a second native layout.
- Donor frequencies and native-tree conversion are imported unchanged from the
  selected H060 observation module. All output fields, class/sample/query/site
  ordering, branch geometry, genuine unary edges, isolated-domain restriction,
  allele-axis width and sham-as-copy semantics stay as in that original
  encoder. Only the five support fields may differ by ordinary FP32 rounding.
- `full_preparation_fast_v1.py:prepare_from_loaded_observation_v1` copies the
  original full recipe's entire function body unchanged. Its encoder import is
  explicitly the fast encoder; episode and cut preparation stay on their
  original modules. Thus complete-parent/focal/roster/source checks and the
  no-pruning structural recipe remain intact.
- `parent_startup_fast_v1.py:seal_then_prepare_one_parent_v1` accepts only a
  fresh instance of the original H060 provider. It loads one original sanitized
  observation, explicitly supplies it to that fresh provider, calls its
  unchanged legacy `seal()`, retains the local state through the provider's
  normal release, and prepares the fast global bundle from that same state.
  It always releases provider state in `finally`. No method/global is
  monkeypatched. No live provider can be migrated into this helper.

The one-parent helper returns `(legacy_seal, bundle, new_global_seal)`.
The legacy seal is generated by the unchanged original block encoder and
hash/coverage logic. The new global record hashes the actual new bundle in the
original ordered tensor serialization, binds the exact four additional fast
source refs before/after preparation and hashing, and binds the legacy seal's
canonical metadata SHA. It makes no historical global-byte identity claim.
The record becomes a durable scientific seal only when a genuinely admitted
caller writes it through the existing guarded all20 observation-barrier writer.
No seal was generated here and no completion/lifecycle authority is supplied.

## Precision, scope and limits

The upstream kernel preserves int64 descendant counts, proper-split membership,
integer mismatch minima and all tied native winners. Summary accumulation is
FP32, while legacy support uses NumPy float64 followed by FP32 casting.
Historical support/global bytes and hashes are not promised. Old hash guards
remain mandatory; new global features receive a fresh genuine source-bound
seal. Legacy block sealing stays unchanged. Never insert fast values under an
old digest or relabel an old result.

All original20 complete2Mb TRAIN parents,1600 samples,1000 queries,600 references,
10000 focals, native trees/sites/identities, both learned tree passes, both arms,
600 additional updates per arm, and all20 observed preparations before TRAIN
truth remain required. The adapter provides no target resolver, optimizer,
model forward, training runner, scheduler, admission, retry, resume or fallback.

The default kernel uses32-marker chunks and caps its main int64 count tensor
at8,388,608 elements. This excludes PyG/gather/mismatch scratch and other state;
it is not a measured RSS fit. All existing process/cache/output/time guards,
96GiB complete-parent cache charging, and original source mutation checks remain
required in a future caller. One observation state is held for one parent,
then released before the caller admits the returned bundle to its cache.

This avoids one observation reload and the fast global encoder's duplicate raw
layout call. Legacy block support/layout work still executes unchanged, native
trees are still constructed for the block seal and for global preparation, and
learning-time work is unchanged. No measured speedup or current-phase/bottleneck
claim is made. Parent-wide primitive caching is deliberately absent.

`source_map.v1.json` for provenance. `fast_source_refs.inactive.v1.json`
contains review-input identities only, with no execution authority.
