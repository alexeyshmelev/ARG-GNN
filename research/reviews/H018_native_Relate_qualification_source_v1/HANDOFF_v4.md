## Residual sampled-inventory limitation

An active recursive directory walk is not an atomic filesystem snapshot. A file can be created, grow or disappear between samples, including a transient aggregate/file-count excess unseen by a completed scan; the nominal selector timeout is not a guaranteed sampling interval when metadata calls take time. A disappearing entry may also be omitted by filesystem iteration without an explicit error. The repair tolerates only the narrow explicit disappearance/stale-handle race and does not turn sampled active inventories into a hard filesystem quota.

Kernel per-process file-size limits, original process/time/RSS/log supervision, stage-boundary guard checks, bounded complete scans and stable terminal caps remain. Stable terminal checks run only after the native group is drained, so authorized native cleanup is finished. A server-enforced subtree quota or atomic filesystem snapshot would provide a different aggregate bound, but no such available author/runtime capability is established here. Skipping active finalizer inventory or excluding its scratch tree would weaken the existing aggregate checks and was not adopted.
