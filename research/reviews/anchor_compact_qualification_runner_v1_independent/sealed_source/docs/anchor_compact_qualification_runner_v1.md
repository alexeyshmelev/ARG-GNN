## Qualification gate and retained failures

The sealed adapter chooses the deduplicated minimum-tree, maximum-tree and minimum-readout tiles from exactly the two frozen TRAIN parents using manifest metadata only, with parent/tile ID tie breaks. The runner uses that exact admitted selection. Neither outputs nor timings select tiles.

For N selected tiles the runner executes exactly 8*N+10 numerical probes. Each selected tile has both plain/age geometries, CPU float64 and CUDA float32, seed101 initial full coupling, and both independent-signal action VJPs and full-model/clipped-AdamW probes. The minimum-tree age tile additionally has both probes on the frozen rate/mixture stress state in both devices and the three explicit initial-state scalar/diagonal/gain-matched controls' action probes in both devices. Controls use qualification_direct_control_models_v2 and the same explicitly requested view coupling.

Each default performer uses the sealed loader. Every loaded tile gets full-file and full-field integrity plus all sealed Q184/R96/Q120, feature, coordinate and gather joins. The performer checks returned loaded tile identity, constructs the sealed seed101 pair, verifies the backbone and exact initial/stress parameter state before transfer, and then calls the sealed numerical probe. The runner requires the exact returned performed geometry/native/compact coupling, probe, dtype, canonical device and G/P/Q/R/A/S/latent/depth identity. The separately recorded performed request binds tile/seed/state to that checked construction. Requested labels cannot overwrite returned helper labels.

The runner requires all expected raw-action/output/source/mass families, feature and parameter VJPs, active norm1 clipping, updated parameters and every AdamW step/first/second moment family. It checks the unchanged numerical tolerances, nonempty finite metrics and coherent per-family PASS flags. AdamW scalar step state remains float32 even in a float64 model, matching the sealed helper's actual tensor dtype. No-label and all-Q evidence are mandatory. The clipped optimizer operates on the sealed helper's private copies.

Every attempted cell is saved independently. An exception or numerical failure preserves its requested cell, raw returned metrics when available, and error. Remaining frozen numerical cells are recorded, but no profiling occurs unless every exact planned cell passes. A profile or final-source failure similarly leaves all earlier artifacts and a FAIL report. Files are never overwritten or deleted by the runner. A failed actual condition requires root's versioned repair/repeat decision and independent review before any new attempt.

## Exact profile boundaries

Only the complete frozen PASS gate supplies the exact bound parity receipt to the sealed profiling helpers. Each selected tile/geometry uses initial full coupling, float32, chunk128 and fresh seed101 equivalent state for every sample. The eight stage definitions are:

| Stage | Timed boundary |
|---|---|
| encoder | Finite feature guard and inherited encoder on all280 leaves |
| source | Both layers' query/reference projection and tanh, Cqr source and mass construction, using each layer's cached correct input |
| action | Both layers' finite raw action, mixture, finite/positive mass guard and normalization, using cached sources |
| decoder | Both layers' anchor/target gate, projection and LayerNorm plus final all-Q head, using cached correct inputs/messages |
| forward_with_grad | Complete context and all-Q head with autograd |
| backward | Frozen all-Q objective backward; fresh forward/objective outside timing |
| optimizer | AdamW step; fresh forward/backward/active clipping outside timing |
| full_step | zero_grad(set_to_none), full forward, frozen objective, backward, active norm1 clipping, AdamW |

These constituent stages use the same equations and complete rows as the frozen implementations. Cached intermediate stages measure both inherited layers, with their prerequisite graph outside the boundary. They are not additive because their timing boundaries overlap prerequisites and autograd work. CPU handmade stage tests compare their cached source, action and decoder results exactly with each implementation's complete context.

cuda_profile_pair_v1 provides three warmups per implementation, ten measured samples per implementation, alternating native/compact then compact/native over five ABBA blocks, synchronization at both ends, wall seconds and CUDA-event milliseconds, setup seconds and every allocator baseline/absolute/incremental peak. The runner retains every raw sample, validates pair coverage/order, and reports each numeric field's median/min/max plus all ten paired native/compact wall ratios and their median/min/max. Stage setup includes fresh model/bank transfer and prerequisites outside the measured stage, so setup is reported separately. No ratio is called an established speedup.

For each tile/geometry, three native and three compact guarded load-to-step samples retain:
- Diagnostic full-file hash, deserialization and full-field fingerprint wall timings. Every such diagnostic deserialization is full-file/field checked before discard.
- The separately measured actual sealed guarded load, including all source/admission, full-file/field and identity guards.
- Compact metadata extraction, CPU dtype conversion, synchronized model/bank transfer, complete compute-step and matched guarded load-to-step wall times.
- Fresh model and optimizer setup included in the matched total.

Diagnostic constituents are measured separately from the authoritative sealed loader. They overlap its work and are never added to its matched total. This explicit distinction avoids pretending that separate instrumentation reconstructs the sealed loader's exact time. CPU buffers remain warm as the OS decides; no disk-cold-cache claim is made. Matched guarded load-to-step and matched compute are reported separately. The original currently running candidate's lighter load path is not measured or reclassified.

cuda_isolated_memory_v1 separately runs three footprint probes per implementation. Factories capture only CPU banks, construct fresh CPU seed101 models, transfer only the chosen implementation to its own device, run the complete full step and return its live state/output. The sealed helper rejects more than1MiB live own Torch tensors, synchronizes and flushes only the own allocator cache outside timing. This probe includes transfer through optimizer and excludes the other implementation's device bank. Allocator median/min/max byte summaries and all raw baselines and peaks remain separate from NVTOP/driver context and other-process memory. Unique CPU backing-storage byte estimates and aliasing/segment counts are recorded as provenance, not a claim of CPU footprint reduction.

Sources, receipts, live own lease/context/determinism/inventory and owned storage are rechecked before arrays, between numerical cells, around profiling stages, and at completion. Production boundary artifacts preserve each newly observed raw NVTOP snapshot, own runtime/lease identity and rechecked source-byte map. Boundary writes and the final report are included in the owned cap checks. Every selected geometry remains in the report, including slowdowns or tiny differences. There is no fitting, accuracy, novelty, trained-trajectory, early-stopping or checkpoint-selection claim.
