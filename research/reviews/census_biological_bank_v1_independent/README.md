## Content and source trust boundaries

The adapter accepts already decoded native trees, tensors and explicit observed role rows. Its source records validate only role/path/digest syntax. They do not verify actual artifact bytes, prove that decoded objects came from those files, establish observed rather than truth lineage, or establish the meaning/order of a caller's role roster. The independent fabricated-source-record probe is deliberately accepted. Replacing a supplied hash and resealing can be accepted when the caller also supplies that new digest. An independently frozen digest plus byte-verified reader and immutable inputs are therefore essential, as stated in the adapter docs. Current source/config/job pins must include the adapter itself and executed reader, not just the dependency list.

Preparation enforces numerical value equality plus dtype/shape/stride, not byte-for-byte equality. `torch.equal` accepts stored−0.0 where the producer emits+0.0. The independent probe confirms admission and distinct certificate hashes. This is a narrow nonblocking semantic caveat: both zeros have the same numerical feature value, and byte changes after digest freeze fail. Either describe producer replay as value-exact or strengthen its check before claiming byte-identical replay. Full file-byte admission remains independently required.

No scaler or role-reader implementation was admitted in this scope. F47 still includes original age and observed-reference TMRCA summaries. Dropping only parent branch7 does not make a condition age-free. Native census350 is an observed-tree gate, and older references provide class proxy evidence rather than census target assignments.
