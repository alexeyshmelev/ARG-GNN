H038 expanded released AncestralPaths Dense adapter
==================================================

This is source-only authoring. Root owns experiment registration, runtime,
storage, execution and scoring admission. No actual parent, target or fit was
opened by the author. The draft config is a policy/source handoff, not admission.

The callable APIs and exact references are in receipt.json. Prepare each completed
registered TRAIN/VAL parent through read_completed_parent_v1 and prepare_parent_v1.
Each caller supplies an exact completion reference. The reader verifies frozen
producer/config/registry lineage, nine observed files, post-five-iteration tree,
actual flagged nodes and sample ages, complete476-diploid order, and original/
local/VCF SNP joins. It refuses oracle annotations in the inferred tree. All952
inputs remain; queries are686, includingBAA14. Donors remain266 with unequal
Ana50/CHG28/WHG102/EHG86 counts and34 older source-deme prototypes. Their observed
source roles are retained; census descendants are never invented for donors.

The feature stage reuses the existing full-roster cache adapter, which changes
only the old cache helper's280 diploid-range cardinality to952. Native features
are five informative shells with nine columns in Bronze,BAA,Yam,Neo,WHG,EHG,Ana,
CHG,int(age)/1500 order. They preserve incremental leaves, skipped empty shells,
present exclusion, ancient focal self-inclusion, and-15 root padding. Float64
repeated-add normalization precedes float32 conversion for the qualified runtime.

TRAIN truth is a separate exact external full_truth_intervals.npz reference.
Only TRAIN query path1..6 labels enter the unchanged v2 realized sampler and
Dense categorical targets. Each parent preserves source_num_seq=3 and10000/3
overhead. Targets are50k/50k/12.5k/25k/25k for Present/Bronze/BAA/Neo/Yam; scan
budgets are100k/100k/25k/50k/25k, matching the author script. Caps are12.5k per
non-BAA path and6.25k perBAA path. Float step+=step/2, native site/sample order,
duplicate multiplicity, and bounded128-pass/no-progress shortfalls are preserved.
Requested total is5,200,000 rows for32TRAIN, but only genuine realized rows fit.
Shortfalls are reported; caps are not increased and no phantom rows are padded.

fit_all_train_v1 requires exactly32TRAIN manifests. The released architecture is
Flatten5x9, Dense512/ReLU, dropout0.2, Dense6/softmax, categoricalCE and default
Keras Adam. Fit uses batch32, shuffleTrue, five epochs and final epoch5, without
VAL selection/calibration/early stopping. Seed101 is a declared new seed. Fit
requires the existing qualified TF2.15.1/Keras2.15.0 CPU prefix. No package install
or GPU launch is part of this module. It is a released Dense adaptation, not
reproduction of the unavailable published CNN or original numerical experiment.

seal_parent_predictions_v1 reloads the bound final checkpoint for each of8VAL
parents and opens no truth. It predicts every observation-defined original100bp
center for all686queries, retains clipped edges and excludes unobserved tails.
It exports C4 probabilities in Ana,CHG,WHG,EHG order by summing p1+p5,p2+p6,p3,p4
before argmax. This is a derived source endpoint, not a separately retrained
BAA-excluded four-path author model. A separate native6_SNP_focal product keeps
unmasked six probabilities on the source test traversal,10k requested rows per
query cohort. Its50k/25k source path caps cannot bind below10k total rows per
cohort, so selection is observation-only. Any realized shortfall remains explicit.

native_focal_metrics_v1 is a pure post-seal scorer over externally supplied labels.
It preserves unweighted sample accuracy and predicted-row/true-column six-path
confusion/precision, with cohort results separate from physical C4 scores. Common
C4 physical scoring and any target authorization after seals remain root-owned.
Outer parents are rejected by these preparation/prediction APIs.

All writes require a root guard and fresh project-local outputs. Exact compressed
writes are guarded by size; the unchanged legacy cache/selection helper receives
a conservative maximum-byte guard before its native writes. Existing outputs
are never replaced. No new monitor, launcher, storage journal or source edit to
author/pilot/helper code is introduced.
