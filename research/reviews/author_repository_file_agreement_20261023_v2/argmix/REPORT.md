3. `train_joint_model.py` is the actual trainer. It requires `num_refs + 1` archive width, seeds 50, globally shuffles native chunks, trains AdamW and selects strict minimum mean validation-batch loss with patience. The shipped template and frozen common-data recipe use 15 references, hidden 128, four layers/four heads, projected features 16, raw cM span, chunks 1,024/stride 512, bidirectional GRU 128, batch 16, maximum 20 epochs, learning rate 2e-4, weight decay 1e-4, label smoothing 0.1, patience 2 and train-only nearest-reference drop 1. The project/backend fallback epoch maximum is 3, so 20 is the template/recipe setting, not a universal fallback. Single-layer GRU recurrent dropout is zero under PyTorch semantics despite its configured 0.1.
4. Current CLI inference derives checkpoint geometry, exports the base model, runs Rust workers and applies joint GRU refinement by default. Generic component APIs are more flexible than this full path. The normal exporter rejects ancestor metadata and derives references + 1, but `--seq_len` and a raw-state branch remain available for suitably supplied weights. This is a recoverable component, not evidence of paper weights or a supported paper trainer.
5. Current `argmix test` invokes `final_test_metrics.py`. It expands interval calls onto covered retained truth SNPs, intersects diploid haplotype coverage, reports SNP/cohort/class accuracy, dose correlation squared and coverage, and computes haplotype jackknife intervals. With an empty TEST split it warns and falls back to validation. Neither that denominator nor the jackknife defines the April sampled-subgraph table statistic.

## Surviving components and precise source discrepancies

**Ancestors survive.** `sample_iterator.rs:536–585,648–662,1261–1283`, `fast_lca/engine.rs:932–954`, `extracted_batch.rs:68–88` and exports in `lib.rs:114–124` retain parent-chain ancestors and the 1 + references + ancestors geometry. Short chains use PAD. A learned CLS token is added later, so a reconstructed 29-node genealogy would have 30 transformer tokens with this model. `FastBenchmarkRunner` accepts ancestors but discards batches and returns throughput counters, so it is not a ready training exporter. The deprecated incremental engine has reference-only geometry. Full project/config/archive/trainer/checkpoint inference paths still reject or force zero ancestors. Merge-on also rejects ancestors, while merge-off preserves raw dimensions.

**Donor labels must remain distinct from targets.** Paper paragraphs 9/47 include informative admixed Neolithic farmer and Yamnaya references in a four-founder ancestry task. `commands/infer.py:114–121` requires every reference population to be an output-class name, blocking distinct admixed donor tokens with that target head. The generic transformer vocabulary can represent such tokens. A paper-oriented interface adaptation must decouple donor vocabulary from target classes rather than falsely relabelling an admixed donor as a pure founder.

**Relative key index differs from the displayed equation.** Paper Eq. 3 is `q_i dot P_query[psi(i,j)] + k_j dot P_key[psi(i,j)]`. `tmrca_attn.py:111–114` computes `k_i dot P_key[psi(i,j)]`. Because psi usually varies with j, this term generally varies across the attention row and does not generally cancel in softmax. A row-constant term would cancel in special cases. Even in such a case the paper term can vary with k_j. No model accuracy effect was measured. The inactive exact diff gathers key scores at the transposed distance and transposes the result back, preserving the original asymmetric psi(i,j), query term, value term, mask and scaling. It is an equation-aligned algorithm variant, not unchanged release code.

**Raw linear clipping can wrap before clipping.** Current release defaults use floored `log2(1 + distance)` with cap 14, unlike paper psi's raw 1,000-generation ceiling. A linear option exists. In the fast engine (`:827–835`) the absolute delta is cast to u16 before `min`, so 65,536 generations encodes zero and 65,537 encodes one instead of 1,000. This particular defect is in the raw linear option, not the unchanged current log-scale condition. The inactive diff clamps in u64 first and only then narrows, preserving missing-LCA behavior. The legacy SampleIterator floating cast saturates and avoids that modulo wrap, so unmodified legacy raw-cap extraction is another source-backed component option for the existing rounded node times.

These raw/legacy APIs still require explicit donor sufficiency, self/sister exclusion and tie rules, exact sample-time treatment and geometry adapters. The shared selector breaks equal-distance ties by input reference index and duplicates the last reference when too few candidates exist. Source rounding/truncation is not confirmed paper discretization. Native archive reference IDs originate from HashMap iteration, and equal-distance ties break by reference input index. Archive group iteration also makes global chunk order dependent on HashMap order. A fixed seed alone therefore does not identify the realized native corpus. Current native HDF5 feature payloads retain fp16 bit patterns in u16 storage even with fp32 D2H transfer, then decode to float32 before joint refinement. Preserve actual archives, selected references and feature dtypes with hashes. Optional ids_only merging can retain the first numeric matrix across changed times; the maintained release recipe explicitly disables merging. Deprecated incremental cache caveats are separate from the active fast-only route and have no measured benchmark effect.
