# FLARE source-build executor and native runner successor

Status is source only. The executor and successor compile. Neither was imported/run; there was no acquisition, extraction, Java/javac/JAR, guard, reservation, admission, process query, scientific-data read, installation, GPU or Git action in this implementation task. Earlier official metadata remain pinned by the original plan. The old runner v1 and original plan are unchanged.

The executor API is build_executor_v1.execute_v1(admission_ref, guard=callback). Root supplies a partial of its already configured existing v3 guard:

    callback = functools.partial(current_v3_guard.budget_check_v9, actual_storage)
    completion_ref = executor.execute_v1(exact_admission_ref, guard=callback)

This is a source example, not an executed command. The callback must return the actual matching reservation; the executor verifies it at strict pre/post boundaries. It never imports/configures/replaces accounting. The inactive draft requires exact executor/plan/source-manifest/toolchain/runtime refs, one fresh .runtime/FLARE_java_source_build_jdk11_v1 scope with no auxiliary scopes, exactly1GB reserved, nproc4 CPU,2GB host-RSS enforcement attestation, CPU-only, unexpired root authority and an externally enforced3600second process-group deadline. Root owns all admissions and execution. Current mutex/NFS concerns must be resolved by root before any actual admission; this task does not change guard replay or locking.

Downloads stream through bounded chunks with exact bytes/digests, a200MB aggregate receive cap and128actual request/redirect cap. The JDK release URL,195609919bytes and SHA256 are immutable.96Java URLs/sizes/Git blob SHA1 values are exact commit pins. Sources are fetched without Git/source archives/test datasets, and all Java bytes are checked before compile, after build and inside the final JAR. Any mismatch fails with partials preserved.

The SHA-qualified JDK is scanned before extraction: one explicit root, <=20000members, <=650MB per decompressed tar traversal, canonical paths and no special files. Relative symlink/hardlink targets must remain inside that root, exist and resolve without cycles. They are materialized as separate ordinary nlink1 files/directories, with original link metadata retained. Duplicated content and allocation allowances are included in a600MB conservative JDK bound before extraction. Every extracted/materialized regular file has a content SHA256 checked and recorded in JDK_contents.jsonl. This normalization was expressly authorized because the unchanged existing guard rejects literal symlinks/hardlinks.

One compilation and one JAR build follow the official README classpath, entrypoint and packaging, using JDK11 class target55. No native Java source or FLARE option is changed. Root's newer nproc4 instruction replaces the original plan's two-processor build resource proposal. JVM operational flags disable hsperfdata and place tmp/home/error outputs in scope; core dumps are disabled. JAVA_TOOL_OPTIONS/_JAVA_OPTIONS/JDK_JAVA_OPTIONS are removed for the builder. All six tool calls have explicit actual waits, bounded RAM stdout and owned process groups; nonzero/timeout/RSS/product-cap failures stop without fallback. During compiler/JAR activity there are no guard/mutex calls or parent disk writes in scope. The complete child-growth allowance is checked before that sequence and strict auditing follows quiescence. Own child walltime/RSS and bounded output observations stay active. Xmx and these contractual storage checks are not OS quotas or total-JVM-RSS proofs; root's actual host enforcement remains required.

The successor removes live guard calls while the native JAR writes; preplanned growth and strict post-wait boundaries remain. It records/prints the actual native wait, terminates only its newly created process group on errors and requires group ESRCH before guarded evidence/artifact writes. Scientific native execution still needs separate root review/admission and the exact successor source closure. No fallback method/marker/sample/option alteration is added.

Caught tool failures emit actual wait evidence to root stdout and preserve available failed.json metadata when the owned group is quiescent and the original guard permits writing. SIGKILL, host loss, a blocked external callback or unwritable storage can prevent local persistence; never infer a missing return code from process absence. No automatic replay or cleanup deletion is implemented.
