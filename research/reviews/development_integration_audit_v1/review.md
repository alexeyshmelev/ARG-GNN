## Findings

### ID-01: artifact paths could escape the project, corrected during audit

The original candidate and temporal protocol validators accepted arbitrary model-name strings. An absolute model ID such as `/tmp/audit_outside_project_no_write` passed validation, and `checkpoint_root / (name + '.pt')` evaluated to a path outside the project. Traversal IDs could likewise escape their fresh run directory and reach other project artifacts. No outside write was performed. `config_guard_reproducer.json` records the admitted original IDs and path calculation.

Root added a full ASCII model-name check to both isolated runners during this audit. The corrected validators reject absolute paths, traversal, separators, hidden-name starts, control characters and overlong names while preserving ordinary IDs with letters, numbers, dots, underscores and hyphens. Independent direct checks cover six rejected and three accepted patterns in each runner (`audit_checks.json`). This defect is resolved in the examined patched versions. It never affected the preparation wrapper.

### HASH-02: config drift could misbind fitted settings, corrected during audit

The original runners had a concrete provenance defect. Root corrected both during the audit, and independent regression reproducers verified rejection before accepted-result sealing. It never blocked the separate preparation execution.

In `train_anchor_temporal.main`, settings are parsed once, but checkpoint and prediction protocol hashes are recomputed from the live config file. No unchanged-config check runs before sealing. The synthetic CPU reproducer changes only its own config after the first validation call. The fit succeeds. `results.json` and copied `protocol.json` bind SHA `34656bd77086979acd6bfda19b37fabf7550e89e98b7558342580d39e46f2031`, while the saved prediction/checkpoint bind the changed config SHA `4ddbe4a16084be41f228fedb46713526b7e6e39efc7c3a2442dd8f4733fd5d29`. Fitting still uses the originally loaded settings. The executable case is `audit_checks.py`, and results/logs are `audit_checks.json` and `audit_checks.log`.

The candidate runner has the same class of gap despite its required startup `--expected-config-sha256`. It re-reads config bytes for its protocol copy and later recomputes `config_sha` after dataset preparation. In a tiny synthetic case, the config is changed from width8 to width16 inside the dataset-load callback, after the initial exact-hash check. Fitting remains width8 but the copied protocol declares width16, the recorded digest becomes `311c49d43183ab1e9dbb95fc3d3a3374daba3e646cb8d2eb91230a32ba3eae82`, and the run completes. `candidate_config_drift.json` records this. Only the production count validator was replaced to permit the one-parent fixture; hash checks, protocol copying, model factory, fitting and artifact storage were actual runner code.

Root now captures config bytes/SHA at admission, verifies consistency after parsing, writes the captured protocol bytes, reuses the original SHA in artifacts and rejects config drift before accepted-result sealing. Both stored drift reproducers were independently rerun against the fixed runners in fresh temporary folders. Both raised "Frozen configuration changed during training", produced no accepted results.json, and kept generated protocol/checkpoint/prediction digests bound to the original bytes. The candidate protocol copy also retained the actually fitted width8. Evidence is `postfix_regression.json`. HASH-02 is resolved in the final examined versions.

### DEV-03: fresh temporal execution remains separate work

`train_anchor_temporal.py` is a pilot/general train-validation runner. It has no required exact-config SHA argument, no fixed `[101,202,303]` seed admission, no fresh-development namespace/count restriction and no full eight-configuration grid budget guard. Its search-plan JSON correctly states proposal-only. This is harmless for its declared pilot scope. It would block use of this file alone as the claimed mandatory fresh-development runner. Root reports a separate dedicated temporal development adapter has been assigned; that new adapter is outside this audit snapshot and needs its own admission checks.

Candidate development does enforce exactly64TRAIN/16VAL/TEST0, the three declared seeds, its namespace, all eight plain/age × depth1/2 × LR configurations and fixed dimensions/budgets. One allowed subset per invocation does not imply a completed search. Family selection across every required configuration/seed and the prespecified parameter-count/ID tie rule remains later synthesis work as documented.

### PLAN-04: validator flexibility is a limitation of future freezes

The concrete preparation plan retains coverage>=0.95, grid>=120, packed nodes<=1,000,000, electrical cap1e12 and40GB RAM admission. Its exact current freeze binds those choices and cannot be changed during active preparation. No current execution blocker was found.

However, `load_plan` permits a newly authored plan to relax admission thresholds and `minimum_cpu_available_bytes` before making another freeze. A read-only synthetic call admits1byte RAM, coverage0.01, one retained grid point and packed-node cap1,000,000,000. `audit_checks.json` records the call. This is not a bypass of the current hash-bound freeze, and root has not authorized such revisions. If these values are intended to be mandatory invariants across every v1 freeze, enforce their minima/maxima in `load_plan` rather than relying only on current config bytes. No preparation source was changed while its CPU job was active.

### FINAL-05: metric tools alone do not enforce final evaluation

The paired-parent helper correctly averages seed-specific losses within parent, uses parents as independent units, bootstraps entire parent vectors, retains seed-specific diagnostics and conditions inference on the fixed training cohort/checkpoints. It intentionally accepts generic checkpoint counts and IDs. A future final runner must enforce exactly the three frozen checkpoints/seeds, method/parent correspondence, sealed predictions before label joining and fixed analysis budgets. The current documentation expressly leaves that work open. No final cohort was generated, read or scored here.

## Scientific and integration checks that passed

- Neural model inputs use the same observed47-field plain source GNN path, same physical anchors and original query correspondence. Plain source numerators/masses match the frozen candidate in the contract tests. References stay independently encoded/clamped. External labels and baseline scores are absent from model inputs.
- Readout addition, duplication and permutation preserve sources and existing deterministic predictions. Query permutation and numerical ID renaming preserve correspondence. Physical coordinates remain globally bp/1e6; interpolation fractions are computed in float64. Decoder readouts are independent of one another.
- The GRU and Transformer differ in capacity, query exchange and decoder structure, and the smoother uses an observed role/Cqr subset with no fitting. Those are disclosed scope choices, not equal-parameter mechanism ablations or exact external baseline reproductions. Age-candidate source geometry differs from the comparators' plain Cqr geometry and is explicitly documented.
- Raw NLL uses float64 stable log-softmax with no probability floor. Historical floor diagnostics stay separate. Parent validation selection gives each parent equal weight and retains the earliest exact checkpoint tie. Extreme-logit tests expose uncapped NLL1000/2000 where historical scores cap below28.
- Query/coordinate scatter guards reject incomplete/duplicate mappings. Actual tiny CPU checkpoint/prediction round trips preserve raw NLL and coordinates. Temporal saved logits are original float32 in a float32 model run, subsequently evaluated by float64 log-softmax; this preserves model outputs and is a harmless precision/storage choice. Candidate saved logits are float64 copies of model outputs.
- Preparation uses fixed split IDs and masters, the actual installed simulator/inference seed functions, collision checks across240 proposed streams and prior declared streams, fixed confined output roots, no overwrite/resume, label-blind coverage/electrical/canonicalization admission and failure ledgers. Shared API signatures match the calls. Whole parents are checked before tiling. The original target/query/coordinate pairing uses existing exact verification.
- Code/config/dataset hashes are recorded and implementation/config drift is checked before sealing. HASH-02 was corrected and independently verified during this audit. File hashes recorded after Python imports also rely on the operational no-live-source-edit rule to describe the loaded code faithfully; the current root freeze honors that rule.
- Resource guards are conservative storage estimates and refreshed scans, CPU-only preparation, eager loaders, a dense attention-score guard and normal GPU launcher/lease checks. The Transformer guard does not bound all activations/backward/allocator memory and is documented accordingly. No empirical larger-cohort runtime/memory guarantee follows from these CPU correctness checks.
