# Independent ordered-marker learning source review

**Decision: SOURCE_BLOCKED for representative-learning integration.** The scientific contrast and forward computation are meaningful as a narrow development hypothesis. I found no core mismatch in the intended H058 feature algebra, no new truth input and no reduced observation support. Three concrete implementation/provenance items must be resolved before this source can support a representative learning route. This is an independent source/AST review, not a numerical, gradient, memory, speed or ancestry result.

The candidate's eight sealed files authenticate exactly. Thirteen of fourteen declared source refs match. The experiment-ledger ref is stale at this review snapshot. The original model, kernel and binding refs themselves match. I also inspected and pinned the actual inherited clade/PyG model sources rather than accepting the earlier kernel toy's verdict.

## Blocking findings

1. **Dense fallback loses the original inner backward lifetime boundary (P1).** At positive_marker_backend_v1.py:274, marker_sequence calls dense.marker_features_v2 directly. Its block size limits a single invocation to16 markers, but the new whole-hold feature graph contains every such invocation. The original PackedSameMarkerEvidenceV2.forward at same_marker_packed_csr_v2.py:433 checkpoints each block_statistics call; the new route bypasses that wrapper. The outer checkpoint around _hold_residuals does not establish the original one-block activation bound during backward recomputation. Its dense per-block graph includes [N_t, B·8·4] seed/up/outside tensors and message/scan intermediates. Worst-case backward accounting must allow these across the hold, in addition to the explicitly retained [S_t,Q,24] feature/mask sequence and GRU activations. Current prose discusses feature/GRU lifetime and inherited stage checkpoints, but that does not account for this changed dense backward term. Restore an equivalent differentiable inner block checkpoint, or explicitly bind and account for the larger backward lifetime before a representative route is accepted. This is a source-level loss of a prior memory boundary, not evidence that an actual parent has exceeded memory.

2. **The new initializer omits an original trainability/FP32 failstop (P2).** initialize_supplied_h045_v1 at ordered_learning_gnn_v1.py:154 checks supplied old-state tensor dtype, shapes, count and zero new outputs. It does not check every model parameter's requires_grad and dtype. The original initialize_supplied_h045_state_v3 at integration_hooks_v3.py:101 does. A model whose gate or other new parameters were frozen after construction still satisfies the new helper's predicates, while violating the proposed all-weights-trainable comparison. A partially recast new module is likewise not checked by the helper. Constructor defaults are correct; that does not restore the accepted-input contract. Restore the all-parameter FP32/trainability predicate before this initializer certifies the model. No parameter, marker or training-budget reduction is an acceptable substitute.

3. **One declared provenance ref no longer authenticates (P2).** SOURCE_CONTRACT.v1.json declares research/experiment_ledger.md at c7f8f603af31ca247e879686ec583f71e423ae900a2ae6c5085a8db7763061ae. STATIC_AUDIT records the different bytes observed at review time. The shared ledger is mutable, so this is not an allegation of a model-source change. Freeze the relevant provenance in an immutable receipt, or explicitly identify a historical ledger revision and its retrievable bytes; a future active source closure must authenticate all refs it claims to bind. Preserve the present candidate and drift evidence.

## Feature and biological semantics

The sparse and dense routes implement the same intended quantity: for each group/allele, a positive sum of child-edge path weights from references outside the query node's subtree. Groups remain class plus4×1[age>=350]. Reference sequence assignment uses the original route permutation, while query calls stay in their original columns. Only known pure-reference identities seed the added allele evidence. Mixed/context/query identities remain in the complete backbone but do not become labeled source seeds.

Cover construction uses observed reference calls only. The homogeneous covers partition reference observations without assuming a unique mutation origin. Mixed states split into smaller covers or singleton sampled references. Missing reference regions seed no allele; explicit four-allele slots preserve multiallelic and recurrent patterns. A missing symbol prevents a called homogeneous cover from accidentally including an uncalled reference. No query genotype or ancestry target chooses a cover.

The outside-only cases are correct by source algebra. A cover inside the query subtree contributes nothing. A disjoint cover contributes its upward group sum multiplied by the query-to-cover path. For an ancestral cover, the positive side sums along query-to-cover ancestors retain sibling/local-reference contributions and exclude the receiving subtree, without subtracting nearly equal masses. Root gamma is excluded by path construction. These observations cover the internal-query algebra, although the actual packed preparation contract currently requires all original sampled leaves; this review does not certify a new arbitrary-internal-sample layout.

Called counts remain all called references in a group, rather than only outside references. Ordinary frequency, matching contrast, mass normalization, availability values and pooling masks match the original H058 source. In particular, called references with zero outside mass retain safe_logD=0 and valid=1. That unusual behavior is inherited deliberately, not repaired or relabeled as a calibrated likelihood. All-missing query holds get a zero ordered residual through the explicit availability mask. Missing positions within a partially observed hold remain positions in the recurrent sequence.

## Learned comparison, capacity and gradients

The new sequence is read before mean/max reduction. A bidirectional GRU's two final states are generally order-sensitive. Each native hold resets this added GRU; physical SNP gaps are not supplied. The existing genomic BiGRU still crosses the chromosome's complete native holds for all952 sampled identities.

The parameter arithmetic is consistent: Linear24→8 has192, the bidirectional GRU has864, Linear16→8 has128 and Linear8→32 has256, totaling1440. Added to31812 H045 and714 H058 parameters this gives33966 in each arm. The positive backend adds no registered learned module. This is analytic allocation accounting, not a model-instantiation check.

Both arms retain the common H058 pooled residual, clade/episode coupling, two complete original PyG sweeps, sampled contexts, genomic BiGRU and classifier. The same ordered query-row vector is added before sweep2 in feedback and at the corresponding sampled query contexts after sweep2 in readout. All original identities and output support remain. A win tests placement of identical ordered information, not whether marker order itself is valuable; both arms already receive order. Comparing against H058 alone is not a capacity-matched order ablation. The report states those limits appropriately.

The score→sigmoid→log-gamma→positive/dense feature→GRU/residual path contains no new detach or learned-field cache. Cover/fallback branches depend on observations/structure, so they do not freeze current learned gates. Whole-hold nonreentrant checkpointing can preserve this graph, subject to the lifetime finding above. Zero-initialized residual output weights imply that deeper new-module/gate objective gradients may initially be zero and become active after the heads move. Source connectivity is not proof of finite FP32 full-parent backward; the earlier toy does not establish that result for this model.

## Real cost and execution boundary

The original site encoder still processes all S×H categorical observations through its learned19-channel encoder, then pools by native hold. Both full neural tree traversals, clade/episode work and the chromosome-wide recurrent classifier remain. They are not replaced by a graph token or avoided through covers.

New CPU preparation adds reference scalar access O(S·R) and straightforward O(sum_t S_t N_t) structural work, plus Python allocation overhead. Persistent state includes parent/query tuples, sparse-eligible covers, original stamps and256 bytes per site of int64 called-group/allele counts, in addition to the original bank/layout. New parent tuples duplicate structural information already held by the packed route. No full-parent Python-object or cache peak is measured.

Sparse evaluation includes O(N_t·8) grouped fields plus query/cover ancestor/path walks, per-path tensor-index creation and log sums. A suitable path-dependent expression is O(sum_t,s Q·P_ts·(D_query+D_cover)), in addition to feature/GRU work. The fallback proxy P_ts·sum_query(depth+1) is a structural heuristic, not a complete time or backward-memory bound. In many ordinary trees even a small cover count can select dense; no actual fallback fraction is known. One expensive site makes the whole16-marker block dense.

The explicit feature and boolean mask alone occupy120·S_t·Q bytes in FP32/bool. Concatenation copies, masked pooling temporaries, width8 recurrent input/history, recurrent saved state and kernel autograd intermediates add to that. With dense fallback the checkpoint gap can add the larger all-block graph term. Fixed hidden width does not make these costs independent of SNP count or tree size. No speed or fit conclusion follows.

The candidate explicitly supplies a forward hook, not a new trainer, observation loader, positive-plan cache, guarded runner or scoring release. The existing H058 producer still constructs its original models/arms and original payloads; it does not select these new classes merely because the new files exist. That is a disclosed integration boundary, not an additional hidden scientific defect. A future source-pinned caller must connect the new pair/plan to the original complete-parent loss, retain first scheduled update evidence and optimizer/gradient checks, preserve all96 new prediction products before either arm's VAL truth, and keep the original30passes/960updates per arm. This review grants no such authority.

Native-hold logits and original100bp lookup are inherited unchanged. The model cannot create a boundary inside a native hold. Eight reused VAL parents and one seed can support development selection only. The proposed boundary utility gate is interpretable within that resolution, but does not establish fine marker localization, donor-copy paths, calibrated ancestry likelihoods or novelty.

## Usable decision

Keep this candidate immutable. Resolve the three blockers in a fresh source version and retain exact mathematical support/settings. Then re-review the specific deltas and real caller before any representative learning request. Any later fit failure must remain a failure with complete records; it cannot be answered by fewer samples, markers, holds, trees, passes or queries. Model imports, instantiation, synthetic/numerical tests, data/payload reads, guards, live resources/processes, admissions, launches and Git were not used in this review.
