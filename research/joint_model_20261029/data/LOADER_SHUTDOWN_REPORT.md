# DataLoader shutdown correction

Python 3.11's resource_sharer owns each sending worker's AF_UNIX listener in its project-local multiprocessing temporary directory. SocketListener registers an implicit unlink finalizer at priority 0. Its socket and daemon resource-sharer thread can still be open when that finalizer unlinks the pathname. NFS preserves the open inode as `.nfs*`; the temporary-directory removal finalizer at priority -100 then raises EBUSY. This accounts for exit-zero runs with interpreter-shutdown tracebacks. Explicit DataLoader shutdown alone reproduced the exact error on both test workers.

`loader_shutdown.py` fixes the ordering without changing paths or libraries. Register `register_worker_resource_cleanup()` inside the existing `initialize_worker`; it registers the current worker's `multiprocessing.resource_sharer.stop(timeout=5)` finalizer at priority 10, before implicit listener unlink. That method joins its own sharing thread, closes its own listening socket before unlink and closes its remaining descriptor handles. In the trainer's `finally`, call `shutdown_loaders(loader, dev_loader)` and retain its returned worker PIDs and exit codes. PyTorch 2.6.0's iterator shutdown closes its pin-memory thread first, signals only its worker process objects and joins them. Use nested `finally` so activity/NVML cleanup still runs if shutdown reports an exception.

The helper does not scan global processes, alter TMPDIR, remove files manually or close an unrelated loader. It leaves prior logs, jobs and temporary-directory evidence untouched. It imports no remote service or connector. The root-owned trainer was not edited by this agent.

CPU qualification on anogena used Python 3.11 and PyTorch 2.6.0+cu124. The unfixed dense-tensor baseline produced two exact EBUSY tracebacks and retained both temporary directories. Fixed normal completion (128 rows) and early termination with prefetch (8 rows) each produced no traceback, both worker exit codes zero and no surviving worker temporary directories. A real sparse-cache test then processed 16 sites / 600 canonical rows and shut down only the supplied loader's two workers cleanly, while a second independent test loader's workers stayed alive and successfully returned another batch. That second loader was subsequently closed separately by its owner.
