# V8 closed-scope accounting

V8 is the minimal successor to the preserved, unsuccessful V7 activation.
It uses .runtime/storage/project_budget_v8, project_budget_v8.py,
launch_reserved_gpu_v5.py, V8 authority/review/storage kinds, V8 consumer guards
and adapter bindings, and V5 supervisor wait evidence. Every V8 root admission
requires both v6_never_activated_root_attested and
v7_never_activated_root_attested true. Both predecessor journals must remain
absent or empty. V4 original accounting and V6/V7 source, admission, and review
bytes remain preserved.

The credential exception now permits at most sixteen exact identities.
Multiple distinct external_preexisting ssh-agent entries are allowed; at most
one project_credential_only entry is allowed. This accommodates root's public
inventory of five external pre-project daemons and the known project credential
daemon. The policy scope is
cooperative_accounting_bounded_opaque_credential_interfaces_not_global_proof.
No new generic opaque process class is introduced.

All V7 safeguards carry forward: exact PID/start ticks/comm/current-user UID,
pre-project checks for external daemons, root ownership/nondumpability and
no-scientific-scope-write-or-relaunch attestations, recorded scientific PID
exclusion, hash-only canonical project creation environment binding, and pinned
socket device/inode/UID/type. Only genuine cwd PermissionError for an exact
listed identity permits a skip. Identity and applicable bindings are rechecked
around that branch and before return. Descriptor/maps failures do not enable
the exception. No credential contents are decoded or output and no socket is
connected to.

Opaque receipts explicitly record uninspected descriptors/maps and set
local_proc_inspected false. This remains cooperative project accounting rather
than a global writer proof; remote NFS writers and external processes remain
outside observation. Original terminal/lease/completion bindings, stable scoped
measurement, future scope-write/relaunch revocation, scheduler mutex, exact
independent review, and guarded boundary checks are unchanged.

The author packet contains source validation and one bounded synthetic
six-daemon process fixture with narrow new-capacity rejection checks. It does
not perform live process inventory, ledger operations, credential access,
activation, scientific execution, GPU scheduling, or Git operations.
