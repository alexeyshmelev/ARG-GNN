# Prospective confirmatory provenance lock

This pure CPU binder replays completed development evidence and binds explicit prospective workflows, analysis conventions and parent/seed registries before any ID test preparation. It does not create a cohort, an executable generation config, predictions, labels, a calibrated model, or a scientific result. No real lock request or lock is supplied with the implementation. Existing protocol prose remains a labeled proposal.

## Mandatory evidence

The binder first re-runs the completed-source ten-family plan binder in validate-only mode with the actual completion receipt, reviewed scope amendment and all ten family configurations. Its reconstructed plan must exactly match the captured main plan. This enforces the complete producer contracts, including dimensions, numerical policy and truth-free development paths, before generic selection replay.

The lock then independently reconstructs the entire 240-cell matrix from hash-captured run receipts and failure ledgers, loads the real selected state/logit files on CPU and re-runs the selector. A winner JSON or incomplete matrix cannot substitute for this evidence. All nine required baseline families must be resolved and eligible. The candidate configuration and globally strongest eligible baseline are frozen with all three prescribed seeds 101/202/303. If the strongest baseline is the deterministic no-fit reference smoother, each seed retains its separately validated prediction artifact and checkpoint=null. No checkpoint is invented. For both selected primary methods, the binder also constructs the existing pure CPU factory, verifies the actual parameter count, checks exact checkpoint keys/shapes/dtypes and unchanged fixed buffers, loads state strictly, and requires each selected run to attest its applied strict policy and exact original/reloaded raw-NLL equality. It does not run model predictions on actual inputs.

The binder also reconstructs secondary run and ledger references by unique artifact SHA and re-runs the strict secondary selector. That selector re-admits the actual common development data/config/source locks, verifies model state schemas and replay, and checks stored raw DEV NLL using its verified external DEV labels. It never opens confirmatory targets. Every conditional control must be resolved and have an eligible two-LR/three-seed choice. Gain-matched diagonal and static local are always required. Selected age adds matched scalar-age full; selected plain depth 2 adds noncontextual; plain depth 1 has no third control. Secondary results cannot replace either primary choice.

## Executable workflows are required

The executable scope is ID confirmation only. The joined-analysis schema names implemented ID primary/secondary/descriptive coverage and separately lists pending robustness/query-count/OOD/illustration coverage. Capturing those prospective plans and registries does not make their workflows ready.

Actual Python sources for the custodian, frozen prediction runner and joined-analysis runner are mandatory, each with an explicit existing top-level entry point. The binder does not execute those workflows. After capturing the known joined-analysis source, it calls only its public metadata-only analysis_schema_values() helper and requires exact equality to the captured prospective artifact schema. It rejects missing entry points, simple pass/ellipsis/None/raise placeholders and substitutions of metrics or numerical helpers for workflow implementations. These are source-presence checks, not a proof that arbitrary code implements the intended workflow.

A separate captured pre-test workflow-validation receipt must bind all workflow/support source hashes, passed checks and actual evidence artifacts. It must attest checks for label sealing from modeling, no prediction gradients/optimization, sealing all predictions and admission before label joining, one joined analysis, parent/seed alignment and unresolved-primary-failure handling. That receipt is reviewable evidence, not an authenticated signature. The binder does not enforce process/file permissions. Custodian isolation and release remain operational responsibilities of root and the actual workflow implementations.

The support artifacts must pin the actual imported confirmatory_metrics.py and development_execution.py bytes. Runtime evidence must describe an actual CUDA device, allowed physical GPU, required process title, UUID, current Python executable/Torch version, CUDA/build strings and the exact typed strict execution policy. CPU smoke cannot stand in for CUDA evidence. The lock records captured runtime information and current NumPy/SciPy/Torch analysis versions without probing or initializing a GPU.

## Request and API

The API validates without emission unless output_path is explicitly supplied:

```python
from arggnn.confirmatory_lock import bind_confirmatory_lock
result = bind_confirmatory_lock(request_path, expected_request_sha256)
```

The reviewed request has exactly schema_version=1, kind="confirmatory_lock_request", status="reviewed_prespecification_before_test_preparation", test_preparation_started=false, final_test_access=false, workflow_code, support_code, and these existing path/SHA references:

| Reference | Required artifact |
|---|---|
| protocol_json, protocol_markdown | Actual confirmatory_design_v1.json/.md, retained as proposal evidence |
| scope_amendment | Current reviewed ten-family development amendment |
| main_selection_plan, main_selection_receipt | Actual complete producer-bound main plan and replayable selection |
| secondary_configuration, secondary_selection_receipt | Actual selected-candidate-conditioned config and complete control selection |
| runtime_manifest | Actual applied CUDA runtime/software/policy receipt |
| analysis_contract | Full prospective analysis/metric/admission/failure conventions |
| parent_seed_registry | Ordered future ID, robustness-mother and independent demographic parent/seed registry |
| prior_parent_seed_registry | Declared complete prior/development seed registry plus real source manifests |
| workflow_validation | Passed pre-test workflow-validation receipt and evidence refs |
| analysis_schema | Actual source-derived pre-test roster/ledger/NPZ/census join schema and coverage |
| temperature_manifest | Actual VAL-only temperature fitting for every selected method/seed |

All references use exactly {path,sha256}. workflow_code has exactly custodian, prediction and joined_analysis, each {path,sha256,entry_point}. support_code has exactly metrics and numerical_policy, each {path,sha256}. No example request with fabricated reviewed hashes is included.

analysis_contract has exactly schema_version=1, kind="prespecified_confirmatory_analysis_contract", status="prespecified_before_test_preparation", protocol_sha256, training_seeds, nll_policy, confirmation, separate_prespecified_analyses, code_artifacts, runtime_manifest and final_test_access=false. Its confirmation and separate-analysis objects must equal the actual captured v1 protocol. This freezes parent-level inference, primary/secondary multiplicity, raw float64 NLL, seed aggregation, reporting metrics, masks, failure rules, dense-grid conventions and sensitivity designs together with the implementing sources.

workflow_validation has exactly schema_version=1, kind="confirmatory_workflow_validation_receipt", status="passed", final_test_access=false, synthetic_development_validation_only=true, code_artifacts, checks and nonempty evidence_artifacts. code_artifacts equals the combined workflow/support refs. checks maps every name in confirmatory_lock.WORKFLOW_CHECKS to true. Every evidence artifact must exist and match its reviewed SHA.

The CLI requires an actual reviewed request and digest. It writes only when both --write-lock and a new --output path are supplied:

```sh
source /workspace-SR003.nfs2/ARG-GNN/scripts/project_env.sh
export CUDA_VISIBLE_DEVICES=''
cd /workspace-SR003.nfs2/ARG-GNN
"$ARGGNN_PYTHON" scripts/bind_confirmatory_lock.py --request REQUEST --expected-request-sha256 REVIEWED_SHA
```

REQUEST and REVIEWED_SHA above are explanatory placeholders, not an executable freeze. A real emission additionally supplies --write-lock --output NEW_PATH. Missing workflows, incomplete selection, proposal/hypothetical requests, prior test access, source drift or changed evidence reject emission.

## Prespecified registries

parent_seed_registry has exactly schema_version=1, kind="prespecified_parent_seed_registry", status="prespecified_before_test_preparation", protocol_sha256, training_seeds=[101,202,303], analysis_seed=20261115 and cohorts. cohorts has exactly id_confirmation, robustness_mother and demographic_ood. ID has ordered parent IDs 0..191 and target 160; each separate cohort has IDs 0..63 and target 64. The actual ID and mother namespaces/master seeds must match the protocol. Demographic OOD uses an explicitly reviewed separate namespace and master seeds, since v1 did not assign their numeric values.

Each cohort has namespace, ancestry_mutation_master_seed, relate_master_seed, target_admitted_parents and parents. Each parent has parent_id, ancestry_seed, mutation_seed, inference_seed and perturbation_seeds. Seeds must be explicit positive integers. All prospective ancestry, mutation and inference seeds are unique within their purpose across cohorts and disjoint from declared prior/development seeds. ID and demographic parents have no perturbation seed entries. Every mother parent supplies the 11 purpose names in confirmatory_lock.PERTURBATIONS, including all four query draws. The binder freezes supplied seeds; it does not generate them or assert an unimplemented derivation algorithm.

prior_parent_seed_registry has schema_version=1, kind="prior_parent_seed_registry", all_previous_and_development_parents_declared=true, final_test_parents=0, parents and source_artifacts. Its parent rows have ancestry_seed, mutation_seed and inference_seed (inference may be null for an oracle-only source). It must include the actual fresh development source manifest. The exact prior seed tuples must equal the union recovered from all supplied TRAIN/VAL source manifests. Completeness outside that supplied source list is a reviewed declaration, not automatic filesystem-history discovery.

## Publication and limits

Captured bytes are hashed once; duplicate JSON keys, conflicting hashes, escaped/symlinked paths, known held-out namespaces and stat/source drift reject binding. Prospective confirmation metadata is permitted only in explicit metadata locations. All source/checkpoint and run evidence remains development-only. Output is written to an owned in-project temporary file, rechecked, then published by an exclusive hard link, preserving existing files.

The returned lock names primary and secondary seed bundles, every input artifact/hash, applied numerical policy, runtime, analysis versions, registries, complete failure/retry records and the lock implementation hash. It records that no test preparation, final-test access, generation, scientific inference or permission enforcement occurred. Future consumers must verify the lock and all relevant artifact hashes before preparation or prediction. Hash binding does not replace workflow validation, permissions or root review.

CPU tests use an isolated synthetic project with real saved tensor/logit files and actual 240-cell main replay. Producer admission, selected-primary factory schemas and the expensive secondary dataset/factory admission are isolated with explicit synthetic stand-ins; their production guards are separately tested by their owners. Tests cover mandatory calls/replay, conditional controls, checkpoint corruption, summary forgery, missing workflows, runtime/policy/analysis/registry rejection, no-fit smoother bundles, immutable emission and drift. These fixtures never constitute a real production freeze or CUDA admission.


## Mandatory validation temperatures and artifact schema

The protocol reports both raw and VAL-temperature diagnostics. A real ID lock therefore requires temperature_manifest even though primary NLL always remains raw. Its exact fields are schema_version=1, kind="prespecified_validation_temperature_manifest", status="frozen_before_test_preparation", main_selection_receipt_sha256, secondary_selection_receipt_sha256, training_seeds=[101,202,303], records and final_test_access=false.

Each selected method/seed appears exactly once. Method IDs are candidate, strongest_required_baseline and the exact eligible secondary control IDs. A record has method_id, seed, temperature, checkpoint, development_prediction, validation_parent_ids, fit_scope="fresh_development_validation_only" and fit_evidence. Temperature must be positive and finite. Checkpoint/prediction references must exactly match the selected bundle, including checkpoint=null for a no-fit smoother. Ordered validation_parent_ids must match all sixteen actual main-study VAL parents.

fit_evidence points to a real JSON receipt with schema_version=1, kind="validation_temperature_fit_receipt", status="complete", method_id, seed, temperature, checkpoint, development_prediction, main_selection_receipt_sha256, secondary_selection_receipt_sha256, source_binding, validation_parents, fit_scope, unchanged_model_weights=true, final_test_access=false, fit_code_artifacts and fit_record_artifacts. It binds all seven source hashes and the complete ordered validation coordinate/query contracts. Both artifact lists must be nonempty real path/SHA references, and fitting code must be Python source. These receipts and records are reviewed fitting evidence; the binder never fits a temperature or loads confirmatory targets. No actual temperature artifact exists as part of this implementation.

analysis_schema has schema_version=1, kind="prespecified_joined_analysis_artifact_schema", status="frozen_before_test_preparation", analysis_phase="id_primary_secondary_and_descriptive" and exact code_artifacts entries joined_analysis, analysis_cli, metrics and dense_tract_metrics, plus the source-defined roster, ledger, prediction NPZ, primary label NPZ, census JSON, fixed policy and remaining_coverage fields. All sources are captured and must match the actual public metadata helper. The prediction/target NPZ contract uses allow_pickle=false and keeps model inputs separate from external labels/census joins. The implemented phase and remaining coverage are retained explicitly in the published ID lock.

## Published-lock admission before target reads

```python
from arggnn.confirmatory_lock import validate_confirmatory_lock
lock = validate_confirmatory_lock(lock_path, reviewed_lock_sha256)
lock.check()  # full captured byte/source verification
```

validate_confirmatory_lock returns ValidatedConfirmatoryLock(payload, content, sha256, path, capture). Its check(full=True) rejects in-memory payload changes, imported binder-source changes, captured stat drift and actual captured-byte hash changes. The reader requires the complete published ID kind/status/scope, exact current binding implementation pins and NumPy/SciPy/Torch/Python runtime versions, all prospective references and captured provenance. It does not repeat fitting or the development search and does not open any future roster, prediction or target arrays. Later analysis owns sealed roster/admission/prediction validation and must complete it before opening labels/census partitions. This API makes no permission-enforcement claim.
