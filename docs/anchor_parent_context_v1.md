This separate source core implements reset/carry parent context and passes 152 handmade CPU checks. It changes no original anchor_kernel.py, biological_candidate.py, H020 predictions, H023 outcomes or other sealed source. H024 was registered before implementation. The configuration remains inactive. There is no actual bank/target reader, simulation, fit loop, GPU scheduler, budget writer or execution admission. Standard-library source reporting is the default. ## Fixed data and explicit parent entry

TileContextV1 accepts the exact cached tile layout, original fixed operators, Q/R identity vectors, original tree IDs, geometry, per-tree fixed-feature fingerprints and parent/split/native-tree namespace. stitch_context_v1 copies the cached anchor grids and cell masses into their union. It never constructs a new uniform parent grid. Production metadata requires eight original 32-anchor tiles, Q184/R96, one of the four original development parents and its exact native-tree digest namespace. Small generic dimensions are available only through an explicit handmade fixture seam.

The builder preserves clipped occurrences of an original tree. Chronology, contiguous support, half-open graph/readout ownership, integer joins and single ownership of every source/evaluation are checked. Same-tree occurrences spanning a cut retain compatible fixed Cqq/Cqr operators and declared fixed-feature fingerprints. Incompatible cached features are rejected, not deduplicated. Actual producer verification of those feature fingerprints and complete native-tree inventory remains a future root integration gate.

ParentContextV1 exposes the union anchor count explicitly. The original model’s per-tile anchor-count rejection remains unchanged. parent_context_v1 is a separate entry accepting the same original encoder outputs for every cache graph, with clamped reference sources. It updates global anchor contexts through every nonlinear layer; targets are updated readouts and never become new anchor sources.

## Exact directional action and gradients

streamed_parent_action_v1 preserves unnormalized per-scale numerator and matching mass in both directions. The mass source is exactly 1_Q − lambda Cqr 1_R, with lambda in autograd. The original cached eigensystems, physical subhold durations, chronological noncommuting order, learned rates/damping and original _hold_action are retained. Forward accumulation is inclusive; reverse is exclusive, so a source/readout self term occurs once.

At an artificial cut, a readout belongs to the right tile. In reset mode the forward state resets before that event; the reverse output is evaluated before resetting and propagating into the left tile. Carry passes the unnormalized state continuously. Sources remain strictly inside their original tiles. Every call starts with zero exterior states. Parent/split/native-ARG namespaces cannot be stitched together; no state is retained across calls, nonlinear layers or optimizer steps.

Ordinary autograd and optional non-reentrant activation checkpointing preserve dependencies across block boundaries. The source does not detach carry, floor mass or smooth predictions. Requested readouts can be selected in arbitrary original order while all anchor sources participate. Fixed operator blocks can remain on CPU and are transferred/cast per bounded event block; the core does not gather eigenvectors for every parent segment at once. This has handmade CPU cast parity only, not a measured GPU memory or speed result.

## Finite parent update helper

Only after the first 113-check core pass, matched_parent_step_v1 was added as a finite caller-supplied mathematical operation. Each loss callback returns a connected scalar loss numerator and fixed positive query-bp denominator. All callbacks evaluate unchanged parameters. The helper normalizes their aggregate, performs one backward, checks gradients, clips once at norm 1, and updates once. Parameter mutation between loss cells is rejected. There is no data loading or multi-epoch fit runner.

The future four-arm comparison still needs identical parent-step schedules: age/plain × reset/carry, seeds 101/202/303, maximum 30 epochs and 60 parent updates, with the original optimizer/selection/patience design. Historical H020 used up to 480 tile steps and cannot alone isolate a continuity effect. Real fitting remains unadmitted.

## Handmade qualification

The final suite uses separate two-tile cached layouts with 32 anchors each, small Q/R, three original tree identities with one clipped tree repeated across the cut, noncommuting holds, an exact cut readout, and a source/readout coincidence. Float64 and float32 outputs and VJPs agree with the original dense kernel and original per-tile reset reference at the unchanged configured tolerances. Event blocks of 1, 17, 64 and 4096 cover checkpointed and ordinary autograd paths.

The suite checks numerator, mass, normalization, source/reference/rate/mixture gradients, small two-layer original encoder/gate/head contexts, selective target updates through every layer, float64 directional derivatives, and late-loss-to-early-source plus early-loss-to-late-source influence. Cross-cut influence is nonzero under carry and zero under reset. Fixed float64 CPU-cache blocks cast to float32 reproduce the original fully cast action/VJP. Consistently permuting sampled IDs/operators/sources and restoring the output order preserves both values and VJPs.

Reset aggregate loss and parameter VJP match the sum of unchanged original tile objectives at the same parameters. A single aggregate clip and AdamW step matches parameters, gradients and optimizer step counters. Metadata counterexamples reject missing/duplicate event ownership, incompatible tree caches/features, learned fixed operators, sample-order drift, geometry/chronology drift and cross-parent/split/namespace carry.
