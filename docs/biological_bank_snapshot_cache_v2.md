# H020 verified biological bank snapshots V2

This source-only successor removes repeated bank-file reads and full-bank SHA checks from retained CPU/GPU hits. It changes only the scoped TRAIN and VAL bank-loader aliases. The original seven models, tensor fields and ordering, feature/operator float32 policy, coordinate float64 policy, RNG, training objective, VJP, clipped AdamW updates, scoring, sealing, compression, checkpoint selection and write order remain in the original callers.

Each first parent/tile request reads a bounded immutable bytes snapshot and checks its SHA against the externally pinned manifest bank reference. Torch loads only BytesIO of those verified bytes. Every original load_bank schema, roundtrip, dimensions, sample/query/reference roles, features, normalized readout and mixed query flag check follows unchanged. The exact CPU result and approved snapshot remain together for the cache lifetime. Later mutation or replacement of the external disk path cannot substitute other bytes. Hot requests reject changed tile/ref/SHA, scientific configuration or parent joins and apply the original structural/storage/version resident guard, with no bank-path open, hash or stat. Source/manifest identity checks and original scientific epoch checks remain. This intentionally changes bank-path semantics from V1's repeated current-path verification to continued consumption of the retained approved snapshot.

The reviewed consumers do not mutate fixed banks. The inherited guard catches ordinary PyTorch version changes, tensor metadata/storage substitutions and nested metadata/order changes. It does not detect arbitrary .data or external storage writes; those remain outside the reviewed consumer interface. No tensor subclass, per-hit tensor checksum or scientific source rewrite is introduced.

The complete original 32-cell TRAIN/VAL CPU working set has no eviction or oversize bypass. Capacity shortage raises before returning a new bank. Consequently model-outer VAL cannot evict TRAIN. The GPU LRU is unchanged: conservative full transfer upper bounds, whole-entry eviction, and original uncached transfer for an oversized GPU entry. CPU and GPU caller-retained references still need root headroom.

Prospective caps are 64,000,000,000 bytes of approved archive snapshots, 64,000,000,000 bytes of decoded fixed CPU tensors, a separate 64,000,000,000-byte cold decode tensor/stream peak, and the existing 32,000,000,000-byte GPU LRU. Archive tensor storage lengths are inventoried from the original Torch ZIP before decode. The conservative cold charge includes a full BytesIO copy, archive tensor storages and the original prepared object's transfer upper bound, checked before CPU conversion. Python/NumPy metadata, temporary deserialization buffers, allocator overhead and the unchanged models/optimizers/runtime are not claimed to be bounded by these tensor counters. Root must qualify actual whole-set RSS, cold peak and headroom separately. These source caps are not an actual resource admission.

The default module invocation reports inactive source status. Execution requires a fresh V2 source review, separate V2 root phase capability, exact original scientific refs/source pins and active memory reservation. A fit additionally requires one-tile seven-model exact fields/logits/VJP/clipped AdamW/RNG parity plus root measured all32 retention, actual memory/headroom qualification and acceptable throughput evidence. V1 capability schemas cannot authorize V2. The inherited one-tile profile explicitly does not qualify complete working-set memory. No existing worker is patched.

The author replay creates only owned handmade byte/tensor fixtures and one tiny synthetic linear model. It checks snapshot races and external path replacement, no hot bank IO/hash/decode, 128 original-order epoch requests with 32 reads/decodes, all32 retention, separate capacity failures, original resident/binding guards, mock CPU-only GPU LRU bookkeeping, exact forward/VJP/clipped AdamW/state/RNG equivalence, bad-bank original-check rejection, scoped alias restoration and original argv preservation. An AST proof establishes that every original post-IO loader statement and nine original helpers are unchanged. Original source pins remain exact. This is implementation evidence, not measured actual performance or accuracy.
