# Source-only compact CUDA bootstrap v1

This standard-library bootstrap closes the mechanical launch gap between the unchanged shared-lease pool and the sealed compact qualification runner. The runner imports Torch, requires an already qualified own CUDA context, and deliberately configures neither title nor deterministic policy. This bootstrap checks a fresh root permit, sets the exact title, applies the unchanged frozen development policy, establishes the single leased CUDA0 context, verifies actual context UUID and own compute PID/title through the unchanged runner live observer, then calls the exact runner `main` in the same PID. It forks or execs no scientific process and changes no numerical or timing arithmetic.

The protocol and author template are permanently inactive source artifacts. Independent source review and author tests confer no actual execution. The template is `research/reviews/anchor_compact_cuda_bootstrap_v1_author/root_permit_template.json`; copying it rejects before context creation. Only root can authorize activation, independent review, current experiment registration, free-device selection, accounting and operational evidence issuance.

## Same-PID evidence and frozen schema compatibility

The fresh output is created only after base scheduler launch. All new temporary/cache/config paths and same-PID worker stdout/stderr are routed inside it. The bootstrap takes a real raw own-context NVTOP snapshot under output/.launch, then the unchanged runner.observe_live independently checks live lease, title, initialized logical CUDA0, current driver context UUID, interpreter/runtime/policy, and a second NVTOP observation of the same own PID/title/index. Its current exact-title project inventory must equal the admitted device list.

It generates immutable hash-bound runtime, storage, launcher, adapter and runner admission files under output/.launch. These files have root_agent as delegated operational authorizer only because the exact validated root permit authorizes this issuance. The storage domain is copied exactly from root. Other domains record newly observed live evidence. Their runner_config and source maps remain exactly frozen.

The runtime source_sha256 map stays exactly the adapter's complete source map plus runner and runner protocol. The frozen schema permits extra receipt fields, so bootstrap_execution records the exact bootstrap source/config, root permit, independent bootstrap review, separate pool source/config/review and current experiment admission in launcher/runtime/root evidence. All are bound by immutable domain hashes. The bootstrap rechecks its additional source/permit/review/ledger pins before context, before runner invocation and after return. Frozen runner stage checks continue to rehash their original exact source map and domain receipts; they do not add bootstrap source paths to that frozen map.

No failed initial guard reaches CUDA. A context/evidence failure reaches no scientific runner. Every already written output/evidence is retained on failure. Owned-scope checks are stage checks, not continuous quotas; root retains complete accounting obligations.
