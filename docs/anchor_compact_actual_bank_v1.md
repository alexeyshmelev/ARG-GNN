## Exact adapter contract

The model inherits the original encoder, projections, gates, LayerNorm, head, log-rate parameterization and parameter/state-dict names. It substitutes the sealed compact action only. All Q184 anchor and target states, R96 fixed sources, positive mixed mass checks and unique readout/anchor maps are retained. It does not restrict gates or the head to Q120. The same Q120 output-index map is preserved in provenance. Mixed64 rows receive no labels.

The CPU alias view retains leaf features, plain normalized full-boundary response, original query/reference gather vectors, target graph mapping, compact coordinate metadata and the selected fixed eigensystem/Cqr/optional control diagonal. Device transfer copies only these required arrays. It introduces no eigensolve, eigenmode truncation, quantization, stored converted bank, reference relabeling, graph interpolation or coordinate rescaling. Coordinates remain float64 and neural data uses the explicitly selected dtype. Diagonal views alias the full CPU Cqq storage. The full original CPU object remains available for comparison, so CPU footprint reduction is not claimed. The view is mutable aliasing, not an immutable-artifact contract.

The actual loader keeps full original file SHA256 and full-field fingerprint checking on each load. Before extraction it checks Q184/R96 exhaustion, Q120-to-Q184 mapping, source sample identity joins, original feature columns, physical readouts, tile bounds, graph counts and query flags. It reads only selected TRAIN bank arrays. It does not read scientific labels, VAL banks, inferred tree arrays or an on-disk converted cache. It uses the root-hashed full prepared manifest and inherited exact source map as provenance. This is a strengthened common integrity guard for the new engineering comparison. The currently running native candidate's lighter per-use integrity path remains unchanged. Integrity cost must be reported separately and a strengthened-guard timing must not be presented as the original fit's end-to-end timing.

## Frozen numerical cells

Run all selected TRAIN tiles for both plain and age geometry at the original seed101 initialization, on CPU float64 and root-qualified CUDA float32. Run a second data-independent stress state only on the minimum-tree selection with age geometry, again in both dtypes. The stress state uses fixed raw log-coupling values from-.7 to.6, raw log-damping from.4 to-.3 and mixture logits from-.8 to.7 over3x8 channels in each layer. No checkpoint or validation score chooses this state.

For each cell use `compare_action_VJPs_v1` and `compare_model_step_v1`. In revision2 a shared model/view identity guard runs before encoder, projection or action work. Geometry, coupling, scale/anchor counts and feature dtype/device must match. The full-model probe also rejects native/compact model identity mismatches before copying private models. Successful and numerical-failure receipts include `cell_identity` with the actual native/compact geometry and coupling, probe, dtype/device and G/P/Q/R/A/S/H/depth counts. Direct action dispatch uses the checked identities recorded in that receipt. A mismatched request raises before any performed-cell PASS is available. The first compares independent actual encoded first-layer query/reference source signals, raw per-scale action, numerator, strictly positive mass, normalized full-Q output and VJPs with respect to query signal, reference signal, raw coupling, raw damping and mixture logits. The latter compares both complete layers, all source/mass/source-message families, final anchors/targets, all Q184 logits, feature-input VJP and every inherited parameter VJP. It runs one actively clipped matched AdamW step and compares all updated parameters and step/first-/second-moment optimizer tensors. Model inputs are not modified. The utility deep-copies private model states and feature inputs.

The deterministic qualification objective is1000 times a mean nonuniform all-Q logit cotangent plus.013 mean log mixed mass from each layer. This is a numerical probe, not an ancestry loss or accuracy metric. Preclip norm must exceed1 for both implementations. Missing expected gradients, nonfinite quantities, nonpositive mass or invalid gathers fail qualification. Failures preserve their metrics and stop profiling. A parity failure before the optimizer stops optimizer mutation. A post-step failure changes only private disposable copies.

On the minimum-tree age tile, also qualify the three non-full controls with `compare_action_VJPs_v1`, seed101 initial state, CPU float64 and CUDA float32. Construct each pair with `qualification_direct_control_models_v2("age", coupling)` and derive the view with that same explicit coupling. This helper passes the intended scalar/diagonal/gain-matched identity to the inherited model constructor and rejects full or unknown controls. `qualification_models_v1` retains full as its default and accepts a validated explicit coupling keyword. Pairing its default full model with a non-full view now rejects. The runner must compare returned cell identities against every frozen requested cell and cannot relabel a full receipt as a non-full control. These control probes retain original Cqr and, where applicable, the exact Cqq diagonal and full gain-matching transform. They do not fit or compare biological mechanism performance.

## Profiling after parity PASS

Profile initial full-coupling state on each selected TRAIN tile for both geometries, float32, through the reviewed CUDA launcher. Keep deterministic algorithms and the original precision policy. Use no mixed precision, TF32 change, compiler, graph capture or altered row validation. Record exact Torch/CUDA/driver/device UUID, process title, source/manifest hashes, G/P/Q/R/A/S/H counts, native/compact segment counts, dtype, chunks and retained-byte estimates.

For GPU stage pairs, `cuda_profile_pair_v1` takes native/compact factories which create fresh equivalent state before each sample. It uses3 warmups per implementation and10 measured samples each, with pair order native/compact then compact/native repeated five times. Setup time is separately recorded. Stage callables run unchanged finite/mass guards. They return/retain their outputs through synchronization. Full-step state is fresh seed101 for every sample so timing does not depend on parameter drift.

Stages are encoder, projection/source construction, finite action including mass normalization, decoder/gates/head, complete forward with autograd, backward, optimizer, and full forward/backward/clip/AdamW step. Define each callable's exact boundary in the runner. Backward setup creates the forward graph outside its timed region. Optimizer setup performs backward/clipping outside its region. Full step includes zero-grad, forward, objective, backward, clipping and AdamW. Do not sum overlapping stage measurements to infer total fitting speed. CPU wall timings of full-file hashing, full-field hashing, deserialization, compact metadata conversion, dtype conversion and synchronized transfer are recorded separately, with3 unchanged repeats and no global storage walk. No disk-cold-cache claim is made. Report matched guarded load-to-step totals separately from compute-only stages and from the frozen candidate's original load path.

Each GPU sample starts and ends with synchronization, reports wall seconds and CUDA event milliseconds, resets own Torch peak-memory counters and reports allocated/reserved baseline, absolute peak and incremental peak. Event timing omits some host overhead while wall timing includes it. Pair stage peaks may include resident shared comparison banks. They measure stage workspace relative to the reported baseline and must not be described as a whole-pipeline footprint.

`cuda_isolated_memory_v1` provides a separate3-probe-per-implementation footprint condition. Factories capture CPU-only models/banks, allocate/transfer their own fresh device state, execute the full step, and return their live state/output. The helper rejects more than1MiB live Torch CUDA tensors before a probe, clears the own allocator cache outside timing, then measures peak allocation/reservation from transfer through optimizer. This avoids keeping both original and compact device banks resident while making a footprint claim. Report allocator memory separately from NVTOP/driver context memory and other users' memory. CUDA source paths and synchronization are source-reviewed here, not exercised by the handmade CPU suite.

Keep every selected tile and geometry in the report, including slowdowns or insignificant differences. Report per-cell median, min/max and paired native/compact wall ratios. With these few tiles, descriptive variation is not a population confidence interval. Reserve biological fitting-speed comparisons for a separately admitted actual training condition. This protocol measures engineering fidelity and efficiency only.
