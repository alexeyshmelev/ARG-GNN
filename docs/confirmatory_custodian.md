# Confirmatory custodian release

The custodian is a lock-first importer/packager for already prepared ID artifacts. It does not simulate parents, run Relate, infer graphs, train models, predict, choose methods, score targets, or enforce operating-system permissions. Upstream generation remains a separate future workflow. No real published lock or final input example is provided.

`prepare_confirmatory_release(lock_path, expected_lock_sha256, request_path, expected_request_sha256, *, output_directory, project_root=ROOT)` calls the real public published-lock validator before reading the request or any observed/target input. The lock must bind the fixed ID protocol/registry, exact shared analysis artifact schema and current custodian workflow/support sources. `custodian_schema_values()` and CLI `--schema` expose prospective metadata only. Capture every listed support source in future lock validation evidence.

The input request has exactly the fields returned by that schema. It is kind `confirmatory_custodian_import_request`, status `awaiting_label_blind_release`, and binds lock SHA, parent-seed registry SHA, cohort and namespace. Attempts are contiguous IDs beginning at0. Candidate rows use status `admitted`, provide a nonempty observed-only reason, `label_blind:true`, the explicit upstream native-inference return code, and separate observed-identity, primary-label and census references. Rejected rows have null artifact references. The return code is an upstream recorded claim, not a native inference execution by this importer.

An observed identity binds frozen ancestry/mutation/inference seeds, exactly one observed-only NPZ,64 ordered query IDs,32 disjoint diploid index pairs, exact original128/4096 global physical midpoint grids clipped to common coverage, and seven eight-tile edges at125000bp multiples. The observed NPZ has only the shared raw F8 graph arrays and scalar Unicode JSON header. Its topology, all88 sample identities, observed reference categories/dates, query flags, landmark descendants and branches are checked by the frozen predictor's public observed validator. Full-parent electrical reduction and canonicalization are recomputed on CPU before tiling, with node cap1000000, strictly positive resistance and condition bound1e12. No targets enter these calculations.

All observed admission decisions are computed first. Nonzero native return, insufficient observed coverage or observed graph/electrical QA failure stays an explicit rejected attempt. Hash/source/registry/schema failures abort release. The attempt ledger must stop at the first160 admitted parents or exhaust all192 attempts before a shortfall release. Target integrity failure aborts the entire release and cannot silently remove a difficult parent.

The ledger and full locked method×seed×admitted-parent roster are serialized before any target arrays are opened. Custodian-only integrity reads then verify external int64 primary labels against physical positions/query order and exact full-domain census partitions. The primary labels must equal census classes at every retained midpoint. This integrity step does not calculate class counts, model losses or select parents.

A fresh exclusive output directory contains `admission_ledger.json`, `prediction_roster_initial.json`, and `release_receipt.json`. Every initial prediction cell is unresolved, with the exact locked checkpoint and an explicit reason. The complete roster preserves pending cells; it cannot authorize target joining. The analysis runner waits for a complete terminal roster, retains failed cells for descriptive sensitivity, and blocks positive confirmation when required cells fail or precision is insufficient.

The release receipt is the final commit marker. Staged writes are flushed/fsynced, captured lock/source/input hashes are rechecked, and files link exclusively into an owned fresh directory. Fault cleanup removes owned files; a raced unrelated output is preserved. Artifact hashes provide application-level separation and drift detection. Target paths remain visible metadata and no OS access isolation is claimed.

CPU tests use handmade star-tree observations and external target arrays with an explicit mocked positive published-lock validator. They exercise real observed topology/electrical/canonicalization and target-integrity paths, label counterfactuals, drift, failures and partial-write cleanup. A separate negative test uses the actual validator and rejects the synthetic lock before input access. These tests establish no real cohort, final prediction, GPU performance or scientific confirmation.


The first160 count-policy cases additionally mock identity/QA and target integrity to check termination and a1920-cell roster cheaply. They do not establish160 actual independent parents or target joins. All failed-source and initial concurrent-source-drift test logs remain preserved under ignored runtime paths.


Operational roster sealing uses seal_confirmatory_prediction_roster or CLI --seal-roster, with explicit lock/ledger/initial-roster paths and SHA256s plus actual immutable terminal receipt references. Initial entries have terminal_receipt:null. Successful/failed cells require actual predictor terminal records; absent cells remain unresolved with both references null. Success must match the frozen method/seed/parent, observed identity, checkpoint, protocol, grids, source hashes and qualified CUDA stack/hardware/process/lease metadata, with CPU validation false and CUDA execution true. The success NPZ header/query/grid/raw-logit identity and actual bytes are checked before sealing. Failed cells retain actual terminal receipts and null predictions. CPU validation outputs cannot masquerade as operational confirmation predictions.

This mode opens metadata and predictions only, never targets, and emits a new roster/seal receipt without modifying the initial roster. Every expected cell remains present. A complete terminal roster does not itself authorize a positive result; joined analysis separately applies completeness and precision rules. Operational CUDA metadata in CPU unit fixtures is explicitly mocked.

Publication additionally verifies staged directory ownership and each staged/published file inode, stat, size and SHA256 against supplied bytes before links and after final callbacks. Open staged descriptors prevent inode reuse during cleanup. NFS silly-rename cleanup is retried after descriptors close. Foreign file/directory replacements are preserved.
